## 3. 트러블슈팅 메모

### 3.1 포트 8000 충돌 — Cursor IDE가 점유 중
**증상.** `uvicorn --port 8000` 기동 시 `[Errno 48] address already in use`.
**원인.** Cursor IDE의 내부 서비스가 `:8000`(irdmi 별칭)을 LISTEN 중. pkill로 죽지 않음 (의도된 점유).
**해결.** 빈 포트 자동 탐색(`lsof -i :$p`) 후 첫 비어있는 포트(8888) 사용.
**향후 정책.** 운영 배포에서는 Go BFF가 :8000으로 프록시하기로 약속되어 있으므로 ai-service 표준 포트는 :8000 그대로 유지. **개발 머신에서만 동적 포트.**
**기록.** [[decisions_a1_v1#D-9]] 신규.

### 3.2 JSON 파싱 실패 — shell 변수 경유
**증상.** curl 응답을 `RESP=$(curl ...)` 후 `echo "$RESP" | python3 -m json.tool` 했더니 `Invalid control character at: line 1 column 1732`.
**원인.** 응답 자체는 2830 bytes의 valid JSON. **shell 변수 저장 + echo 파이프 과정**에서 binary-safe 보장 깨짐 (특히 `\n`, `\r` 등 escape 문자).
**해결.** `curl ... > /tmp/resume.json` 으로 파일에 직접 받고 python 파서에 파일 경로 전달.
**기록.** [[decisions_a1_v1#D-10]] 신규 — 검증 스크립트 컨벤션.

### 3.3 외부 수정자 개입 — dto/graph/requirements 보강
S1 1차 작성 직후 사용자가 별도 작업으로 다음 보강:
- `dto.py` 신규 (Pydantic 모델 + action별 강제 검증)
- `graph.py` 정책 docstring + `_assign_stable_ids` + `coerced=True` 마킹
- `requirements.txt` 상한 핀 + pydantic 추가

→ 모두 [[decisions_a1_v1]] D-1~D-8과 정합. 별도 sync 작업 불필요. 본 문서에 작업 결과 흡수.
