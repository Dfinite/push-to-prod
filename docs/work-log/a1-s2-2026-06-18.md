## 3. 트러블슈팅 메모

### 3.1 `llm.is_available()` 미존재
**증상.** 프롬프트에서 `llm.is_available()` 체크를 언급했으나 실제 `llm.py`에 해당 함수가 없음.
**원인.** A2 owner 가 작성한 `llm.py`(c421b20 기반)에는 `get_client()` / `call_tool()` 만 존재.
**해결.** `ontology.py` 내부에 `_api_key_available()` 헬퍼 정의 — `os.environ.get("ANTHROPIC_API_KEY")` 직접 체크. `llm.py` 변경 없음(D-11 준수).
**결정 신규 여부.** D-12 항목으로 기록 — [[decisions_a1_v1#D-12]].

### 3.2 ONTOLOGY_TOOL inline 정의 vs llm.py re-export
**상황.** D-11은 "A1 의 ONTOLOGY_TOOL 은 각 노드 모듈에 inline 정의"라고 명시.
그런데 llm.py 에 이미 완전히 정의된 `ONTOLOGY_TOOL` 이 존재함.
**판단.** 완전히 동일한 dict 를 두 곳에 복제하면 D-11 취지(충돌 방지)와 반대로 미래 동기화 문제 발생.
`llm.ONTOLOGY_TOOL` 을 `ONTOLOGY_TOOL` 로 re-export 하는 방식으로 D-11 의도(노드 모듈에 이름 노출)를 충족하면서 DRY 유지.
**결정 신규 여부.** D-13 항목으로 기록 — [[decisions_a1_v1#D-13]].
